# Scripts

`train.py` is the exact worker used on both L4 VMs. `driver.py` runs the paired fits in alternating arm order and skips completed JSON files. Both are mirrored in `results/remote_code/`. Each active fit checkpoints its adapters, FP32 master weights, AdamW state, step and random state every ten steps on the GPU VM. The checkpoint is removed only after the final prediction JSON is written atomically.

For analysis, run `audit_results.py`, `analyze.py` and `figures.py` with the ML environment Python. `report.py`, `blog.py` and `proof.py` render the manuscripts and terminal evidence from actual saved measurements. `validate_artifacts.py` checks completeness, hypothesis decisions, image resolution, word count and compute accounting. `finalize.sh` runs this sequence after all ten confirmation fits are saved and stops the named VM if necessary. Inspect publication PNGs manually before committing.

The remaining scripts record this run's orchestration, not a generic training service. `pilot_register.py` sized the fresh confirmation and committed its plan; its completed job must not be repeated against observed confirmation results. `start_confirmation.py` recorded the start of the confirmation phase. `recover_remote.py` restored the five saved fits onto the replacement VM without changing the training worker. `monitor.py` polls the replacement, copies snapshots and automatically stops only the `qlora-vs-lora` session on completion or failure. `finish_accounting.py` includes both VM lifetimes using saved termination evidence.

For a fresh reproduction use an isolated directory and new GPU session, read the registered README first, and retain model revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`. The historical worker resolves the HF model name at load time and records the actual model revision in every result; it does not enforce a revision argument. Dataset indices, class codes, fingerprints, predictions and token counts are saved under `results/`. Do not overwrite these original results.
